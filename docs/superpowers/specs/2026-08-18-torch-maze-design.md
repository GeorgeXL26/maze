# 火把迷宫 (Torch Maze) — v1.0 设计文档

日期：2026-08-18

## 1. 概述

一款纯 HTML + three.js 的卡通风格迷宫探索游戏。玩家扮演角色在斜45度俯视视角下自由移动，
迷宫笼罩在迷雾中，只有靠近墙上的火把才能照亮周围区域。目标是收集迷宫中的道具并找到出口。

配套一个独立的地图编辑器，方便设计和分享自定义关卡。

美术方向参考《塞尔达传说：智慧再现》/《织梦岛》重制版：Q版比例、粗黑描边、分层卡通阴影、
固定斜角 diorama 镜头。

## 2. 范围 (v1.0)

**包含：**
- 单人迷宫探索玩法（自由移动 + 碰撞检测）
- 火把点亮机制 + 迷雾（fog of war）
- 收集道具 + 找出口的胜负条件
- 传送回最近点亮火把的"防迷路"功能
- 卡通描边渲染（MeshToonMaterial + 反向法线描边）
- 独立地图编辑器（2D 网格画布，JSON 导入/导出）

**明确排除（后续版本再做，但数据结构预留扩展位）：**
- 武器装备系统
- 怪物/战斗系统
- 更多道具类型的具体玩法效果

## 3. 文件结构

```
torch-maze/
├── game.html              游戏本体（唯一入口）
├── editor.html             地图编辑器（唯一入口）
├── shared/
│   ├── maze-schema.js       地图数据结构 + 校验 + buildMazeMesh()
│   └── toon-renderer.js     three.js 场景/相机/卡通材质/描边 封装
├── levels/
│   └── default.json         内置默认关卡
└── docs/
    └── superpowers/specs/   设计文档
```

three.js 通过 `<script type="importmap">` 从 CDN（unpkg/jsdelivr）引入，不使用 npm/构建工具。
两个 html 文件都可以直接双击在浏览器打开运行（不依赖本地服务器）。

## 4. 数据格式

```json
{
  "width": 15,
  "height": 15,
  "cells": ["###############", "#..#..........#", "..."],
  "torches": [{"x": 3, "y": 5}],
  "items": [{"x": 7, "y": 2, "id": "gem1", "type": "gem"}],
  "start": {"x": 1, "y": 1},
  "exit": {"x": 13, "y": 13},
  "monsters": [],
  "equipment": []
}
```

- `cells`：字符网格，`#` = 墙，`.` = 地板。
- `torches`：墙面火把坐标，初始为熄灭状态。
- `items`：道具坐标，`type` 字段预留未来道具种类扩展（v1.0 只有一种通用收集品）。
- `monsters` / `equipment`：预留空数组，v1.0 不使用，为后续版本预留字段位，避免未来改格式。

`shared/maze-schema.js` 导出 `validateMazeData(data)` 和 `buildMazeMesh(data, THREE)`，
game.html 和 editor.html 都引用它，保证两边对同一份数据的理解和渲染基础一致。

## 5. 游戏核心机制

- **相机**：`PerspectiveCamera`，窄 FOV，固定斜45度角跟随玩家水平位置（不跟随旋转），模拟
  diorama 镜头感。
- **移动**：WASD 控制角色在 XZ 平面自由移动，与墙体做圆形/AABB 碰撞检测，禁止穿墙。
- **迷雾**：`scene.fog = new THREE.FogExp2(...)`，指数雾限制可视距离；环境光保持很低强度。
- **火把光源**：
  - 玩家自带一个较弱的 `PointLight`，跟随角色移动，提供基础照明范围。
  - 墙面火把初始 `intensity = 0`（视觉上熄灭，材质为暗淡色）。
  - 玩家进入火把检测半径时，火把强度渐变点亮（配合材质变亮/自发光提升），并记录为
    "最近点亮火把"（存一个 `{x, y}` 坐标）。
- **防迷路传送**：固定按键（默认 `E`）或 HUD 按钮，将玩家瞬移到"最近点亮火把"的位置。
- **道具收集**：走到 `items` 坐标上自动拾取，HUD 显示 `已收集 / 总数`。
- **胜负判定**：仅当道具全部收集后，`exit` 格才生效；玩家到达 exit 格即通关，显示结算界面。

## 6. 卡通渲染

- 基础材质：`THREE.MeshToonMaterial` + 3~4 档灰阶渐变贴图（`gradientMap`），形成分层阴影。
- 描边：反向法线外扩描边技巧（背面剔除翻转 + 沿法线方向外扩一层黑色材质网格），不依赖
  后期处理 pass，性能开销小，兼容纯前端无构建环境。
- 色彩：暖色调火把/木质 vs 冷色调石墙/地板，形成对比，参考塞尔达糖果色调但不过饱和。

## 7. 地图编辑器

- 2D 俯视网格画布（HTML5 `<canvas>`，非 three.js 3D 预览），保持实现简单可靠。
- 工具栏：刷墙 / 刷地板 / 放火把 / 放道具 / 设起点 / 设终点，点击或拖拽绘制格子。
- 顶部控件：设置网格宽高（新建地图时指定尺寸）。
- 导出：生成符合第4节 schema 的 JSON 文件供下载。
- 导入：读取本地 JSON 文件并重绘网格（复用 `maze-schema.js` 的 `validateMazeData`）。
- game.html 启动时可选择加载 `levels/default.json` 或通过文件选择器导入自定义关卡 JSON。

## 8. 测试方式

无自动化测试框架（纯前端无构建项目）。验证方式：
- 手动在浏览器打开 game.html，走查移动/碰撞/火把点亮/雾效/传送/收集/通关全流程。
- 手动在浏览器打开 editor.html，走查画格子/切换工具/导出导入 JSON/在 game.html 中加载编辑好的关卡。
- 边界情况：迷宫边缘碰撞、起点与出口重合、道具在火把点亮范围内提前可见等。

## 9. 美术风格参考

参考《塞尔达传说：智慧再现》/《织梦岛》重制版官方美术与截图（收集于设计讨论中，未内嵌本文档，
避免版权图片入库）：
- 比例：Q版矮小人物，圆润几何形状
- 描边：粗黑描边 + 分层色阶阴影
- 色彩：饱和但不刺眼的糖果色调，暖冷对比
- 镜头：固定斜角俯视、窄视角，diorama 感

这与第6节的技术方案（MeshToonMaterial + 描边 + 固定跟随相机）一致。
